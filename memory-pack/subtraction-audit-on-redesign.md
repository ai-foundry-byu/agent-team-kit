When a design lands on "X IS the surface / there is no special mode / only layer Y changes
here," the surface it supersedes must be AUDITED FOR REMOVAL before or alongside building the
new pieces. Building the new model additively onto the old surface leaves zombie organs —
retired concepts still rendering, affordances writing to the wrong layer — that the owner
then discovers one screenshot at a time, costing extra review loops.

**Why:** agents (and people) instinctively ADD. A redesign that replaces a concept is only
half-implemented if the replaced concept still exists; a hybrid of old and new models reads
as low-fidelity and confuses everyone who reviews it.

**How to apply:** at the start of implementing a design that redefines an existing surface,
write the explicit **kill list** — every component, affordance, term, and data flow the new
model obsoletes. Remove those in the SAME wave the replacement lands, so no wave ships a
hybrid. Ask "what does this design REMOVE?" with the same rigor as "what does it add." See
[[throwaway-mockups-gitignored]].
